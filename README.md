# VecGPT — линии-токены как настоящая языковая модель

> Новая основная архитектура и последовательность её обучения:
> [`VECGPT_TYPED_AST_ARCHITECTURE.md`](VECGPT_TYPED_AST_ARCHITECTURE.md).
> Старая дискретная AR-ветка сохраняется как baseline до прохождения
> typed-AST topology, clothoid-render и temporal gates.

## Architecture v13: conditioning без коллапса

Конечная цель проекта — не raster-to-vector utility. Product path:

```text
LLM hidden states -> direct semantic memory
                  -> optional spatial planning canvas
                  -> variable persistent REGION program
                  -> Stroke sequence
                  -> sparse region deltas + vector cache
                  -> vector animation
```

Реконструкция используется как bootstrap-тест геометрического decoder.
Fixed-set sanity уже доказал, что tokenizer/decoder достигает собственного
потолка. Следующий обязательный gate проверяет не запоминание, а чтение
новых изображений. Старый v12 stage1 с `image_gap≈0` не продолжать.

```bash
PYTHONPATH=. python -u scripts/train.py \
  --stages "1:800" \
  --lr-total-steps 10000 \
  --out-dir runs/v13_conditioning_gate \
  --cache-dir cache \
  --device cuda \
  --hierarchical-regions 0 \
  --dynamic-region-masks 0 \
  --region-attention 0 \
  --eval-n 64 \
  --eval-every 200 \
  --preview-every 200 \
  --ckpt-every 200
```

В логе сначала смотрим `image_gap`: он обязан заметно уйти выше нуля.
`alignment_loss` запрещает visual representation стать константой и связывает
изображение с его Stroke-программой без названий фигур. Экспериментальный
decoder-level `condition_rank_loss` оставлен выключенным: он способен ухудшать
общий decoder вместо улучшения правильной пары. LR короткого запуска больше
не затухает до нуля на последнем шаге.
После 200 шагов уже есть диагностический preview; весь 800-step gate
занимает минуты, а не восемь часов.

Architecture v13 несовместима с v12 checkpoint: semantic memory отделена от
spatial canvas, добавлены foreground/global visual readouts и прямой
conditioning path. Старые результаты остаются диагностикой, новый запуск
использует отдельный `--out-dir`.

Переработка `line_token`. Идея из твоих доков сохранена целиком: сегмент-дуга как
единственный примитив, объект = паттерн внимания, никаких классов фигур,
axial RoPE по осям сегмент/линия. Переделан **выход** и **лосс**.

## 1. Почему старая версия не училась (замерено на твоём коде)

### 1.1 Градиенты разъезжаются на три порядка

Прогнал `scene_loss` на stage2 и посчитал норму градиента каждой компоненты
до параметров энкодера:

```
компонента            значение лосса    ||grad|| в энкодер
direction                 0.171             3.45
type                      0.789             3.22
curv_ce                   5.562             0.638
width/color/alpha         0.059             0.283
pixel                     0.012             0.199
length                    0.003             0.012      <- в 280x слабее direction
position                  0.015             0.0025     <- в 1400x слабее
```

`position` и `length` не тренируются — их градиент утоплен в шуме от
`direction` и `type`. `type` при этом вообще не про картинку («сколько
сегментов»), а забирает больше всех. Adam нормирует по параметру, но в общем
стволе градиенты складываются, поэтому «дать больше шагов» это не лечит.

Причина численная: `position` — Huber с `delta=0.1` по величине из `[0,1]`,
градиент зажат сверху на 0.1 и ещё ужат якобианом softmax по 36 ячейкам.
`length` делится на 6 (mean по `style_idx`) и всегда в квадратичной зоне
Huber. `curv_ce` — CE по 256 классам, ~5.5 нат, на два-три порядка больше
всего остального.

### 1.2 Пиксельный лосс не может «найти», только «дошлифовать»

Радиус притяжения SDF-рендерера, штрих 3px на холсте 48px:

```
смещение  0px -> |grad по anchor| = 0.000
          1px                       0.402
          3px                       0.302
          5px                       0.202
          8px                       0.020
         12px                       0.002
```

Дальше ~8px градиента нет. В начале обучения предсказание отстоит от цели на
пол-холста, так что `pixel_weight=1.0` с шага 0 — это шум поверх и без того
разбалансированных лоссов.

### 1.3 Пропускная способность

**17.8 сцен/с** (batch 8 = питон-цикл из 8 отдельных forward/backward).
Шаг 200 = 1600 сцен = ~9 примеров на класс для 256-way классификатора
кривизны. Константный argmax — ровно то, что и должно получиться.

### 1.4 Корень: вход как у LLM, выход как у регрессии

В твоём доке: `LLM: слово → эмбеддинг → внимание → смысл`. Вход сделан так.
А выход — Huber/MSE по непрерывным числам. У LLM выход это softmax по
дискретному словарю, и именно это делает её устойчивой к неоднозначности.

Регрессия на мультимодальную цель сходится к среднему по модам:
«изгиб +k или −k» → 0 (прямая), «старт с конца A или B» → середина. Ты сам
вывел это для кривизны и починил бинами — но `length`, `xy`, `theta` остались
регрессией, а бины декодировались через `argmax` (недифференцируемо, в
кривизну пиксельный лосс не течёт вообще).

## 2. Что здесь сделано

**Один словарь (1332 токена), один softmax, один лосс в натах.**

```
BOS  [ X Y THETA  (LEN TURN WIDTH R G B)+  EOL ]+  EOS
```

Позиция в последовательности однозначно задаёт поле, логиты маскируются на
легальный диапазон. Все спецголовы (soft-argmax по сетке, sin/cos, отдельные
attention на length/curvature) удалены — они лечили симптомы разбалансировки,
которой больше нет.

Что оставлено из старого: дуга как примитив, axial RoPE головами по осям
сегмент/линия, размер ~7M, fp32.

### 2.1 Сегмент = (длина, УГОЛ ПОВОРОТА), а не (длина, кривизна)

Угол корнера = `κ·L`. При равномерных бинах длины корнерная дуга треугольника
(`L≈0.042`) попадала в бин шириной 7.5% от неё → ошибка угла ~9°, три корнера
разворачивали остаток фигуры на 27°. Полигон, восстановленный **из своих же
токенов**, давал IoU 0.50. Это потолок представления, его не побьёт никакая
модель.

Квантуется напрямую угол поворота, равномерно: 1.4° независимо от длины дуги.
`κ = turn / L` выводится. Выразительность та же, «прямая» = ровно 0.

### 2.2 Канонизация сцены

Направление обхода штриха и порядок штрихов приводятся к единственной форме
(растровый порядок; для замкнутых — знак суммарного поворота). Цель перестаёт
быть мультимодальной по построению, костыль `min(loss_a, loss_b)` не нужен.
Тест `test_canonical_is_order_and_direction_invariant` проверяет, что
перемешивание и разворот штрихов дают побитово одинаковые токены.

### 2.3 Рендерер: линейный ramp вместо сигмоиды

Сигмоида масштаба ~1px на штрихе 1.8px давала в центре coverage 0.7 → цвет
смешивался с фоном (`R=0.758` рисовался как `0.818`) на величину, зависящую
от субпиксельного положения. **Цвет был физически невосстановим из картинки** —
линейный проб по энкодеру не бил равномерный приор. Ramp даёт ровно 1.0
внутри штриха: внутренний пиксель *и есть* цвет.

### 2.4 Энкодеру на вход подаётся ink `(1 − img)`

Холст на 98% белый; сырой вход — почти константа 1.0 с редкой ямкой.
Замерено на изолированном пробе чтения цвета: CE 2.05 → 1.35 нат (приор 2.77).
В полной модели gain по цвету: 0.00 → +0.7 нат.

### 2.5 2D Fourier-код позиции в памяти энкодера

Тот же аргумент, что в твоём доке про Fourier features для времени, только
для пространства: с обучаемым случайным эмбеддингом «какая ячейка → какой
бин координаты» это произвольный lookup, который надо запомнить поячеечно;
с синусоидальным — гладкая функция, обобщается между областями.

### 2.6 Данные не выезжают за холст

Волна уходила за край, канонический якорь оказывался на `x=1.19` — токенная
сетка это не выражает, клипается в 0.996, IoU реконструкции из своих токенов
0.26. Реджект-семплинг + сдвиг.

### 2.7 Label smoothing по соседним бинам

`x/y/theta/len/turn/width/color` — **порядковые**, а не категориальные:
бин 41 не «другой класс» относительно 40. One-hot CE штрафует промах на один
бин так же, как на двести. Гауссиана σ=1 бин по соседям (с wrap для угла)
сохраняет мультимодальность и даёт «близко» смысл. `len`: gain 0.05 → 0.76.

### 2.8 Настоящий батчинг

Векторизованный рендерер считает дистанционные поля всех сегментов всего
батча одной операцией. **179 сцен/с на одном ядре CPU** против 17.8.
На P40 при batch 64 — тысячи.

## 3. Главная метрика: information gain

```
gain(поле) = H_marginal(поле) − CE_model(поле)     [наты]
```

`H_marginal` — энтропия эмпирического распределения этого поля, то есть
ровно то, сколько платит модель, которая на картинку не смотрит вообще.

* `gain > 0` — поле реально читается с изображения
* `gain ≈ 0` — схлопнулось в приор

Это твой `relative_pred_std`, только бесплатно, каждый шаг, и в сравнимых
единицах между полями (потому что теперь всё — один softmax). Видно на
300-м шаге, а не на 3000-м.

Рядом печатается `mae(bins)` — среднее расстояние до правильного бина.
Top-1 accuracy для мелкой порядковой сетки бесполезен: промах на один бин
даёт 0, как и промах на двести.

Бакеты — по **диапазону токена**, не по слоту. Слот `HEAD` несёт и `EOS`, и
`X`; усреднение тривиального поля с трудным как раз и прячет коллапс —
та самая ошибка, из-за которой старая модель выглядела нормально с
константным якорем.

## 5. Запуск

```bash
pip install torch pillow
python -m pytest tests/ -q          # 10 тестов, ~3s

# полный курс на P40 (fp32, ~7M параметров)
python scripts/train.py --batch-size 48 --out-dir runs/v1 2>&1 | tee runs/v1/console.log

# продолжить после падения / перезагрузки
python scripts/train.py --batch-size 48 --out-dir runs/v1 --resume runs/v1/latest.pt

# отчёт по прогону — вот это и отдавать на анализ
python scripts/report.py runs/v1/log.jsonl

# картинки
python scripts/preview.py runs/v1/final.pt --stage 3 -o recon.png
python scripts/preview.py runs/v1/final.pt --ood     -o ood.png
python scripts/preview.py --tokenizer-ceiling --stage 3 -o ceiling.png
```

На старте прогон **сам меряет свою скорость** на твоём железе и печатает ETA
по стадиям — не надо гадать по чужим числам:

```
measured: 163 ms/step  =  196.3 scenes/s (batch 32)
schedule: 58000 steps  ->  ETA 2.63 h   stage1~5.4min stage2~16min stage3~54min stage4~82min
logging to runs/v1/log.jsonl  (hand this file back for analysis)
```

Дефолты: `image=64, d=256, 6 слоёв, 8 голов (3 сегмент / 3 линия / 2 плоских),
batch=32, lr=3e-4, curriculum 1:2000, 2:6000, 3:20000, 4:30000`.

**fp32 обязательно.** У P40 fp16 идёт 1/64 от fp32 — autocast там замедляет
в разы. Памяти 24 ГБ при 7M параметрах избыток, пусти её в batch: попробуй
`--batch-size 64 --d-model 320`.

### Когда станет понятно, что учится

Смотри на `gain`, а не на `ce` и не на картинки. Ориентиры (batch 32-48):

| момент | что уже должно быть видно |
|---|---|
| **~300 шагов** | `eos`/`eol` gain ушли в 0 и `mae 0` — структура последовательности выучена. Если нет — что-то сломано в данных/маске, дальше можно не ждать |
| **~1000 шагов** | `r/g/b` gain > 0.4. Цвет — самое лёгкое поле. Если он плоский на 1000 шагах, модель не читает картинку вообще, останавливай |
| **~2000 шагов (конец stage 1)** | `x`, `y`, `width` gain > 0.3, `mae` по x/y падает ниже 10 бинов. Это гейт «cross-attention научилась локализовать» |
| **~4000-6000 (stage 2)** | `len`, `turn` gain > 0.3. `theta` — самое медленное поле, к концу stage 2 хотя бы > 0.2 |
| **конец stage 3** | eval IoU должен дойти до 50-70% от потолка токенизации (потолок печатается рядом). Меньше 30% — проблема в модели, а не в токенизации |
| **конец stage 4** | разрыв in-dist / OOD. Разрыв > 0.15 = зубрёжка семейств фигур, а не понятия |

Любое поле, сидящее на `gain < 0.05` дольше ~2000 шагов внутри своей стадии,
печатается отдельной строкой `FLAT` — вот это и есть сигнал «вот тут не
учится», с точным указанием чего именно. Больше не надо гадать по сетке
картинок.

### Resume

Чекпоинты пишутся как `stage{N}_{шаг}.pt` **и** как `latest.pt` (всегда
последний). В них лежит и состояние оптимизатора, так что продолжение
точное:

```bash
python scripts/train.py --batch-size 48 --out-dir runs/v1 --resume runs/v1/latest.pt
```

Стадия и шаг внутри неё восстанавливаются из глобального счётчика, имя файла
не парсится. Поток сцен переseedится за уже пройденную точку, чтобы resume не
переигрывал те же самые сцены. Лог дописывается, а не затирается.

**Чекпоинты, сохранённые версией до этой правки, состояния оптимизатора не
содержат** — они грузятся, но моменты Adam стартуют с нуля, и первые
несколько сотен шагов лосс будет хуже. Скрипт об этом честно предупреждает.

### Что нового в этой версии

* **`generate()` больше не может разойтись с обучением.** Слот/сегмент/штрих
  ведёт один `SlotTracker`, общий для обоих путей, и тест
  `test_generation_matches_teacher_forcing` прогоняет ground-truth токены
  через инкрементальный путь и требует совпадения логитов. Именно этого
  теста не хватало: сдвиг слота на единицу оставлял последовательности
  синтаксически валидными, ни один тест не падал, teacher forcing выглядел
  отлично — а генерация давала 2% потолка, и разрыв **рос** по мере обучения.
* **OOD считается по семьям.** Звезда (~20 сегментов), спираль (4-6 дуг),
  крест (2 прямых штриха), клякса (6 дуг, замкнутая) — это разные болезни,
  и усреднять их в одно число нельзя. `report.py` печатает разбивку и
  подсказывает интерпретацию: если лежит `star`, а `cross` в порядке — это
  необобщение по ДЛИНЕ, лечится курсом; если лежит даже `cross` — это
  концепты, и лечится архитектурой.
* **Превью каждые N шагов** (`--preview-every`, дефолт 2000) в
  `{out_dir}/previews/`. Три ряда: цель / реконструкция / **безусловный
  сэмпл** (с null-памятью, вообще без картинки).
* **Conditioning dropout** (`--cond-dropout`, **дефолт 0**, включать `0.1`). Картиночный
  энкодер — леса, а не цель: впереди генерация без исходника, из латента,
  общего с LLM. Обучение с периодически отключённым условием означает, что
  один чекпоинт уже умеет безусловную генерацию, кросс-внимание не выучивает
  допущение «картинка всегда есть», и classifier-free guidance доступен даром.
  Интерфейс уже готов: `model.generate(model.null_memory(n))` — сюда же
  подставится латент LLM.
* **Пространственный bias внимания** (`--spatial-bias`, **дефолт 0**, включать `1`). Обучаемый
  на голову штраф на расстояние между якорями штрихов: близкое дёшево,
  дальнее доступно за плату. `lambda = softplus(raw)`, `raw` стартует с −6,
  то есть **на шаге 0 модель побитово равна модели без bias** — локальность
  появится только если она полезна. Это ответ на «зачем глазу внимание к
  ногам»: дело не в цене O(T²) (она копеечная), а в том, что глобальное
  внимание позволяет выучить ложные дальние корреляции генераторов.

### Что смотреть в логах

```
[s1    300/2000] ce=2.483 lr=7.50e-04 0.9min
    eos:+0.00/0  eol:+0.00/0  x:+0.66/3  y:+0.52/4  theta:+0.93/17
    len:+0.31/9  turn:+0.07/21  width:+0.68/1  r:+0.40/3  g:+0.41/3  b:+0.33/3
    FLAT (gain<0.05, reading nothing from the image): turn

    EVAL  IoU=0.412 (ceiling 0.891, so 46% of what this tokenizer allows)
          strokes 1.0/1.0  empty=0/32
          OOD IoU=0.380 empty=0/32
```

Формат: `поле:gain(наты)/mae(бины)`.

* `eos/eol` gain ≈ 0 это **норма** — они детерминированы, энтропии нет.
* Любое геометрическое поле, сидящее на `gain ≈ 0` дольше ~2000 шагов
  внутри своей стадии — вот это уже сигнал, и видно, какое именно.
* `EVAL` печатает in-dist IoU и **OOD IoU** на семьях фигур, которых в
  обучении не было (звезда, спираль, крест, клякса) — гейт «понятия vs
  зубрёжка» из твоего дока §5. Потолок токенизации на OOD ~0.88.

## 5б. Почему spatial_bias и cond_dropout выключены по умолчанию

Прогон с ними включёнными оказался **хуже** прогона без них на той же точке
(stage 2, шаг 3300):

| поле | без них | с ними |
|---|---|---|
| x | +3.46 / 1 бин | +3.10 / 3 |
| y | +3.31 / 0 | +3.01 / 3 |
| theta | +2.76 / 5 | +2.40 / 10 |
| len | +0.94 / 5 | +0.90 / **27** |
| turn | +1.55 / 4 | +1.25 / 7 |
| IoU | ~75% потолка | 69% |

Часть этого — мой изъян в инструментации: метрики считались по тем же
логитам, что и лосс, **включая 10% примеров, намеренно ослеплённых**
conditioning dropout'ом. Метрика, вся работа которой — сказать «сколько
модель читает с картинки», считалась в том числе там, где картинки не было.
Починено: ослеплённые строки исключаются из `FieldStats`.

Но арифметика не сходится: 10% слепых дают len mae максимум ~10, а не 27.
Остаток не атрибутирован. Пока абляция не скажет иначе, дефолт — та
конфигурация, которая точно работает.

Абляция (по 47 минут каждая, stage 1+2):

```bash
python scripts/train.py --stages 1:2000,2:6000 --spatial-bias 0 --out-dir runs/sb0
python scripts/train.py --stages 1:2000,2:6000 --spatial-bias 1 --out-dir runs/sb1
```

## 5а. Устойчивость канонизации (замерено)

Сдвиг сцены на полпикселя переставляет порядок штрихов в **~1%** случаев
(stage 2/3/4: 1.0% / 0.7% / 1.7%). Тест
`test_canonical_order_is_stable_under_subpixel_shift` держит порог 6%.

Я раньше называл это вероятной причиной OOD-провала — **это было
преувеличение**, 1% слишком редко. Для статики терпимо. А вот для дельта-
анимации это как раз то, что надо заменить на матчинг множеств (DETR-style
ID штрихов) вместо жёсткого порядка: движущийся объект пересекает такие
границы постоянно, и один переворот рассинхронизирует весь кэш.

## 6. Честно: что измерено, а что нет

Всё в разделах 1–4 замерено. Дальше — где я ограничен.

**Тюнинг проверялся на одном ядре CPU**, то есть на бюджете ~20k сцен и
модели 2M параметров. Два вывода оттуда могут развернуться на твоём масштабе:

1. **`n_enc_layers=0` (дефолт).** Self-attention над памятью энкодера при
   700 шагах давал чуть хуже и на 20% медленнее (x: +0.74 → +0.65).
   Логика «дать ячейкам увидеть весь холст до того, как cross-attention
   научится» остаётся разумной на длинном прогоне. Прогони абляцию:
   ```bash
   python scripts/train.py --stages 1:4000 --out-dir runs/enc0
   python scripts/train.py --stages 1:4000 --n-enc-layers 2 --out-dir runs/enc2
   ```
2. **`theta` — самое слабое поле** (gain +0.10, mae 40 бинов из 256 на
   700 шагах, при том что x/y/len/цвет уже идут). Может быть просто
   бюджетом, а может требовать отдельного разбора. Смотри в первую очередь
   на него.

**Не сделано намеренно, с обоснованием:**

* **Схлопывание стиля в 1 токен** (сегмент 6 → 3 токена, ~2x короче
  последовательность и быстрее генерация). Выгода реальная: `width/r/g/b`
  имеют `mae 0` и условно независимы, цепное правило им не нужно. Но это
  refactor ровно той машинерии (слоты ↔ bookkeeping в `generate`), которая
  уже один раз дала тихий катастрофический баг. Делать его в одном заходе с
  тремя другими правками и без бюджета на проверку — способ отгрузить второй
  такой же. Теперь есть parity-тест, который его поймает, так что следующий
  заход безопаснее.
* **Canvas memory (SAM2-style).** Идея сильная и следующая по очереди.
  Ключевой момент для реализации: аккумулятор аддитивен, значит
  `Canvas[i] = Σ_{k<i} F(stroke_k)` — это `cumsum` по оси штрихов, все
  префиксы за один проход. Наивно это O(T) рендеров на шаг и неподъёмно;
  через cumsum teacher forcing стоит почти столько же, сколько без неё.
  Оговорка: аддитивность теряет перекрытие и порядок (painter's algorithm
  не аддитивен) — для «занято/свободно» неважно, для «что поверх чего» важно.
* **Residual/RVQ поверх бинов** — по триггеру «дошёл до ~95% потолка».
  Сейчас 79%: оставшийся 21% это ошибка модели, а не квантования, и поднимать
  потолок раньше — работа впустую.

**Пиксельный лосс не подключён вообще.** Обоснование в §1.2: радиус
притяжения 5px. Если захочешь добавить как финальный дошлифовочный этап —
только после того, как CE-обучение встанет, и только через ожидаемое
значение по softmax (не argmax, он недифференцируем), с раскруткой
`softness_px` от ~8 к 1.

**Cohesion / VICReg из дока §4.2 сознательно не трогал.** Пока
реконструкция не встала, кластеризовать нечего — на коллапснувшем латенте
VICReg покажет красивую дисперсию каналов ни о чём. Порядок из твоего же
§7 (форма → понятия → движение) я не нарушал, просто шаг «форма» ещё не
закрыт.
