> Каноническая спецификация новой основной архитектуры:
> [`VECGPT_TYPED_AST_ARCHITECTURE.md`](VECGPT_TYPED_AST_ARCHITECTURE.md).

## Конечная система (не путать с bootstrap-реконструкцией)

Продуктовый тракт:

```text
prompt / LLM hidden states / scene latent
  -> direct semantic memory
  -> optional learned 2D planning canvas
  -> variable REGION tokens + residual soft masks
  -> nested Stroke program
  -> persistent stroke identities + temporal deltas
  -> vector animation
```

`image -> vector` не является конечной системой. Это только первая
самопроверяемая задача, которая учит decoder геометрии и даёт точный
визуальный loss до подключения LLM. Semantic memory и spatial canvas
разделены: LLM hidden states не притворяются пикселями. Decoder читает
semantic memory напрямую, а spatial canvas использует только когда
локальная планировка действительно нужна.

## Architecture v14: typed vector AST и физический Stroke

Этот раздел заменяет старые ограничения из раздела 0 ниже. Измерения
показали, что один scene latent и одна длинная дискретная AR-цепочка
не являются подходящей основной формой для точной геометрии.

Текущее представление:

```text
ROOT latent                         # смысл всей сцены
  REGION latent ...                 # переменное дерево, следующий этап
    STROKE latent                   # identity объекта/штриха
      FRAME latent (x,y,sinθ,cosθ)  # локальная система координат
      STYLE latent (width,RGBA)     # состояние, записывается один раз
      SEGMENT latent ...            # переменное число геометрических листьев
        STYLE_DELTA?                # только если стиль изменился
```

Это не semantic slots: число узлов определяется программой, а их смысл
возникает в latent через обучение. `max_strokes/max_segments` — только
технический context limit, аналог максимальной длины контекста LLM.

- [x] Векторный autoencoder обучается прямо на Stroke-программах.
- [x] Топология (`present`, число сегментов) предсказывается моделью и не
  подставляется из target при render/eval.
- [x] FRAME, STYLE и SEGMENT имеют отдельные typed latents.
- [x] Differentiable render loss пропускает градиент и в геометрию, и в
  soft topology.
- [x] STYLE хранится состоянием; повторяется только sparse `STYLE_DELTA`.
- [x] Устранено подавление width: физические параметры нормализуются перед
  encoder (`width/0.08`, `length/0.25`, `turn/π`).
- [x] Добавлен накопительный trajectory loss по состояниям `(x,y,θ)` после
  каждого сегмента: локально малые ошибки больше не могут незаметно
  разомкнуть весь круг/полигон.
- [x] Добавлен и проверен дифференцируемый clothoid/Euler-spiral primitive:
  `(L, κ0, Δκ)`, где постоянная дуга — частный случай `Δκ=0`.
- [ ] Добавить REGION как динамический AST-узел между ROOT и STROKE.
- [ ] Перенести основной decoder с bootstrap-реконструкции на
  `LLM hidden states -> typed AST`, оставив vector AE как geometry gate.
- [ ] Добавить temporal AST patch stream и кэш неизменившихся поддеревьев.

Для анимации следующий кадр не генерирует всю сцену заново:

```text
KEEP
REGION_TRANSFORM_DELTA
GEOMETRY_DELTA
STYLE_DELTA
FADE_IN / FADE_OUT
ADD_SUBTREE / REMOVE_SUBTREE
```

Неизменившиеся STROKE/REGION сохраняют identity и используют кэш. Растр
остаётся только обучающим и диагностическим представлением; продуктовый
выход — векторная программа/анимация.

Геометрия параметров остаётся евклидовой + `SE(2)` для frame и окружностью
для угла. Гиперболический канал имеет измеренное основание только для
иерархии REGION: на полном 3-арном дереве глубины 5 Poincaré в 2D дал
distortion `0.224` и parent recall `0.840`, Euclidean 2D — `0.280/0.617`.
Поэтому планируется product space: Euclidean geometry × hyperbolic
structure, а не гиперболические координаты линий.

Clothoid toy gate (512 случайных кривых) показал, сколько постоянных дуг
нужно для аппроксимации одного `(L,κ0,Δκ)`-сегмента:

| Constant arcs | Parameters | Mean point error |
|---:|---:|---:|
| 1 | 2 | 0.03709 |
| 2 | 4 | 0.00918 |
| 4 | 8 | 0.00231 |
| 8 | 16 | 0.00058 |
| 16 | 32 | 0.000145 |

У clothoid три параметра, все проверенные градиенты конечны и ненулевые.
Это не новый семантический объект, а более ёмкая физическая модель того же
единственного Stroke.

Короткий CUDA gate typed-AST на смешанных straight/arc/shape сценах:

| Вариант | Steps | Strict IoU | Shape IoU | Topology/count |
|---|---:|---:|---:|---:|
| raw physical inputs | 600 | 0.492 | 0.637 | 1.000 / 1.000 |
| scaled width/length | 600 | 0.524 | 0.703 | 1.000 / 1.000 |
| + safe trajectory loss | 1000 | 0.539 | 0.717 | 1.000 / 1.000 |

Первый trajectory-loss с масштабом position error `0.10` был отклонён:
он дал `grad_norm=239` и временно уронил Shape IoU до `0.580`. Принят
только безопасный вариант с масштабом `0.25` и весом `0.5`; его preview
показывает замкнутые контуры, а не только улучшенную агрегатную метрику.

## 0. Что считаем неизменяемой основой

На этом этапе **не добавляем новые графические примитивы**.

Единственный примитив остаётся:

```text
Stroke:
  anchor = (x, y, theta)
  segments = [(length, turn/curvature, width, color, alpha), ...]
```

Заливка, пятно, контур, штриховка и сплошная область должны выражаться
траекторией и параметрами `Stroke`, а не отдельными понятиями «круг»,
«заливка», «глаз» и т.п.

Не меняем без отдельного измеренного основания:

- дискретные токены и общий softmax;
- дугу постоянной кривизны как сегмент;
- локальные параметры длины и поворота;
- единую декларативную грамматику;
- канонизацию неоднозначных последовательностей;
- авторегрессивную генерацию.

Главная проверяемая гипотеза следующего этапа:

> Настоящая иерархия регионов, в которой каждый регион владеет своими
> дочерними регионами и штрихами, улучшит обучение и OOD-обобщение на
> длинных композиционных сценах.

## 1. Сначала зафиксировать baseline

Текущий checkpoint сохраняется как baseline плоской архитектуры. Его не
используем как доказательство работоспособности регионального плана:
текущие coarse-регионы сериализуются отдельно от большинства штрихов.

Для baseline сохраняем:

- stage 4 результат;
- время одного train step и generate step.

Текущий незавершённый прогон можно закончить только как baseline. Он не
должен задерживать исправление иерархии.

## 3. Сделать регион настоящей структурой

Плоский список независимых регионов заменить вложенной сериализацией:

```text
BOS
  REGION_BEGIN rx ry rt
    STROKE ...
    REGION_BEGIN rx ry rt
      STROKE ...
    REGION_END
  REGION_END
EOS
```

Допустимы два типа содержимого региона:

- принадлежащий ему `Stroke`;
- дочерний `Region`.

Для одиночного штриха отдельный регион можно не создавать, но тогда этот
штрих должен принадлежать ближайшему существующему родителю. Identity
frame допустим только для корня сцены без явного региона.

### 3.1 Требуемые инварианты

- Каждый штрих принадлежит ровно одному региону.
- Каждый некорневой регион имеет ровно одного родителя.
- После encode/decode сохраняются дерево, принадлежность и геометрия.
- Локальные `x/y/theta` вычисляются в системе координат владельца.
- Квантование родительского frame выполняется до вычисления локальных
  координат, как и сейчас.
- Порядок детей каноничен и является функцией геометрии.
- Грамматика остаётся единственным источником переходов и масок.

### 3.2 Что передаётся модели

В `collate` и модель должны доходить:

- `region_idx`;
- `parent_region_idx`;
- `region_depth`;
- принадлежность каждого токена/штриха региону.

На первом эксперименте эти данные используются только как позиционные
метки. Ограничение attention пока не вводится, чтобы отдельно измерить
эффект самой правильной сериализации.

### 3.3 Тесты

- Структурный round-trip дерева.
- У каждого штриха ровно один owner.
- Локальная геометрия round-trip после квантования frame.
- Паритет teacher forcing и incremental generation.
- Перестановка независимых ветвей после канонизации даёт одинаковые
  токены.
- Ошибка в одном дочернем регионе не меняет системы координат соседнего.

## 4. Честная диагностика плана и утечки

Глобальный `shuffle_ce` сохраняем, но не используем как единственное
доказательство.

Для каждого поля и каждого региона измеряем четыре режима:

1. правильное изображение + правильный prefix;
2. перемешанное изображение + правильный prefix;
3. правильное изображение + испорченный plan prefix;
4. полный rollout с планом, предсказанным самой моделью.

Основные величины:

```text
image_use(field) = CE(shuffled_image) - CE(clean_image)
plan_use(field)  = CE(perturbed_plan) - CE(clean_plan)
exposure_gap     = metric(oracle_plan) - metric(predicted_plan)
```

Leak probe строится на связанных парах:

```text
(plan конкретного региона) -> (штрих этого же региона)
```

Планы других регионов не смешиваются в один неразмеченный вектор.

Положительный `plan_use` сам по себе не является утечкой: план и должен
помогать. Проблема возникает, если:

- `plan_use` высокий;
- `image_use` около нуля;
- rollout с предсказанным планом резко хуже teacher forcing.

## 5. Эксперимент A — иерархия без ограничения attention

Сравниваем:

- A0: текущая плоская baseline;
- A1: вложенная грамматика и правильный ownership, но глобальное attention.

Одинаковыми должны быть:

- набор сцен;
- число optimizer steps;
- batch size;
- размер модели с допустимой небольшой компенсацией embeddings;
- curriculum;
- seed;
- способ eval.

Запускаем минимум три seed после короткого smoke-run.

### 5.1 Предсказание гипотезы

Если полезна сама декомпозиция координат, A1 должна:

- уменьшить ошибку anchors на stage 4–5;
- уменьшить деградацию с ростом числа штрихов;
- улучшить `deeper/wider/chain`;
- не ухудшить stage 2–3 больше измеренного noise floor.

Если этого нет, region frames сами по себе не решают проблему длины.

## 6. Эксперимент B — region-local attention

Только после A1 добавляется маска внимания.

Токен штриха видит:

- токены собственного штриха;
- prefix своего региона;
- предков региона;
- небольшой глобальный summary сцены;
- при необходимости ограниченный набор соседних регионов.

Он не видит детальные токены произвольных чужих ветвей.

Отдельные global heads можно оставить без локальной маски для пропорций,
симметрии и композиционной согласованности.

Перед вычислением spatial bias локальные anchors обязательно переводятся
через `rx/ry/rt` в мировые координаты.

Сравниваем:

- B0: вложенная грамматика, global attention;
- B1: жёсткая region mask;
- B2: region mask + несколько global heads.

### 6.1 Критерий успеха

Region attention считается полезным, только если выигрыш растёт вместе со
сложностью сцены:

- короткие сцены: разница мала;
- длинные/глубокие: B1/B2 устойчиво лучше B0;
- выигрыш повторяется на нескольких seed;
- нет резкого роста exposure gap.

## 7. Curriculum

Резкие переключения стадий заменить постепенной смесью:

```text
stage 2: 100%
переход: stage 2 75% + stage 3 25%
переход: stage 2 25% + stage 3 75%
stage 3: 100%
```

Небольшой replay старых стадий сохраняется дальше. Это позволит отличить
реальную архитектурную деградацию от реакции на мгновенную смену
распределения.

Сокращать stage 1 до 200–300 шагов можно только после парной абляции.

## 8. Метрики результата

Обязательные:

- strict IoU;
- shape IoU;
- tokenizer ceiling;
- физическая ошибка `x/y` в пикселях;
- угловая ошибка `theta/turn`;
- относительная или log-ошибка длины;
- правильное число штрихов;
- валидность и завершённость дерева;
- качество по бакетам числа штрихов, глубины и длины токенов;
- clean/shuffled/perturbed-plan CE по каждому полю;
- oracle-plan против predicted-plan rollout;
- скорость генерации.

Средний token CE не используется как главный критерий архитектуры.

## 9. После подтверждения иерархии

Только если вложенная архитектура выигрывает на stage 5:

1. Реализовать KV-cache.
2. Обучить полноценный unconditional режим и измерить структуру, а не
   только способность `decode()` принять результат.
3. Добавить текст как второй источник памяти:

```text
text/latent -> region plan -> local strokes
```

4. Проверить композиционное текстовое OOD.
5. Затем переходить к временной идентичности штрихов и анимации.

## 9.1 Динамические REGION-токены и возникающие soft masks

Вложенная грамматика сначала проверяется с детерминированными регионами,
полученными только из геометрии штрихов. Это bootstrap-разметка структуры,
но не названий объектов.

Фиксированного банка slots и заранее заданного `K` нет. REGION создаётся
авторегрессивно самой последовательностью:

```text
encoder feature map
  -> динамический REGION token
  -> скрытый вектор REGION запрашивает feature map
  -> обучаемая soft heatmap/mask
  -> локальные Stroke или новые дочерние REGION
  -> REGION_END
```

Число REGION переменно и ограничено только контекстом, как число токенов
в LLM. REGION не имеет класса или заранее заданного смысла. Его скрытое
представление и heatmap обучаются только через качество последующих
предсказаний.

Обучающие сигналы:

- реконструкция токенов принадлежащих региону штрихов;
- реконструкция итогового изображения;
- покрытие чернил масками;
- устойчивость region latent к переносу, цвету и небольшим деформациям;
- предсказание дочерних регионов из родительского latent.

Геометрические регионы используются как временная токенизация структуры,
аналогично тому как текстовая LLM получает границы токенов, но не готовые
понятия. Soft heatmap не задаётся этой токенизацией и возникает внутри
сети. После подтверждения работоспособности структурный bootstrap можно
постепенно dropout'ить.

Проверка появления концептов проводится только через замороженную сеть:

- кластеризация region latent без label supervision;
- retrieval одной формы/части при другом цвете и положении;
- линейный probe, labels которого не участвовали в основном обучении;
- swap/intervention: перенос latent части между композициями;
- compositional OOD — знакомая часть в незнакомом сочетании.

## 10. Что пока сознательно не делаем

- Не добавляем новые типы фигур.
- Не добавляем отдельную семантическую заливку.
- Не добавляем DSL повторов без данных с настоящими повторами.
- Не увеличиваем разрешение квантования до достижения текущего потолка.
- Не увеличиваем модель вместо исправления структуры данных.
- Не называем чтение plan-токенов доказательством полезности плана, пока
  не измерено качество принадлежащих ему штрихов.
