# План исправления VecGPT — простыми словами

## Что сейчас сломано

Автоэнкодер уже умеет восстановить отдельные clothoid-линии. Но diffusion
пока плохо собирает из линий целый объект.

Причины:

1. У линии нет отдельного описания её масштаба и положения.
2. Количество активных линий не генерируется diffusion-моделью.
3. Модель зависит от искусственного порядка линий.
4. У линии слишком бедное геометрическое описание: 16 глобальных probes.
5. Обратный sampling пока не использует тот же scheduler, что обучение.

## Что делаем

### Шаг 1. Усиливаем векторное описание

Для каждой clothoid-линии храним:

```text
локальные sampled points кривой
локальные касательные и кривизну
локальные UDF probes
глобальные x/y/масштаб
толщину и цвет
```

Это всё математические данные, не картинка.

### Шаг 2. Отделяем форму от размещения

Форма линии кодируется в local latent. Отдельно храним:

```text
center_x, center_y, width, height
```

Так diffusion не обязана одновременно угадывать форму, размер и положение.

### Шаг 3. Diffusion генерирует presence

Каждый stroke-токен будет содержать:

```text
shape_latent + bbox + style + presence
```

Не будет принудительного «включить хотя бы одну линию».

### Шаг 4. Убираем зависимость от порядка

На обучении порядок активных линий будет перемешиваться. Позиционные embedding
для индекса линии убираем или заменяем на геометрическое позиционное описание.

### Шаг 5. Проверяем по уровням

1. AE: оригинальная линия → реконструкция.
2. Diffusion: случайные новые векторные скетчи.
3. Категория: `fish`, `car`, `frog` и т.д.
4. Текст.
5. Время и анимация.

Пока предыдущий уровень не работает, следующий не запускаем.

## Чего не делаем

- не переводим внутреннее представление в PNG;
- не используем SAM2 и регионы;
- не добавляем фиксированные semantic slots;
- не маскируем плохой sampling принудительным включением stroke;
- не считаем низкий diffusion loss доказательством хорошей генерации.

## Найденная причина v7

Наш адаптер делил каждый SVG path на четыре части и затем молча обрезал
список до `max_strokes`. Поэтому в кеше 740/2000 примеров имели ровно 64
штриха. Это искусственный сигнал, из-за которого diffusion училась включать
почти все слоты. В StrokeFusion исходный stroke не режется таким образом, а
переполненные примеры отбрасываются collate-ом.

Исправление: по умолчанию один SVG path превращается в один clothoid;
разбиение включается только явным `--split-paths`. Также presence-признак
приведён к соглашению StrokeFusion: активный `+0.5`, padding `-0.5`.
Среднее число штрихов датасета не используется для генерации.
